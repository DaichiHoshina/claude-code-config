# Purpose Traceability

仕様を実装へ分解するとき、判断のつながりを文書に定着させる。目的から Phase までの対応は説明の代わりではなく、文書内の目的・条件・Phase をたどる索引として使う。作成するのは `/sdd-plan` の作業計画書だけで、`/sdd-phase-design` のPhase 詳細設計には置かない (100 行が目安の文書に索引は不要で、Step 3 の「受け入れ条件と担い手の対応」「契約」「テスト観点」の 3 項目と二重になる)。

## 表だけにする (図を作らない)

`Context → Purpose → 受け入れ条件 → Phase` の対応は**表で表し、Mermaid の図を作らない**。

理由は、この 4 段のうち図にできる情報が存在しないことにある。Context と Purpose は 1 対 1 でつながるので節の見出しが示す。受け入れ条件と Phase の対応は 1 段の多対多で、表の「担当 Phase」列がそのまま示す。図にしても表の同じ列を矢印で書き換えるだけで、表に無い情報が増えない。

2026-09-17 に、この図の形を 6 回変えて確かめた。向きの変更、label の文字数の上限、Purpose ごとの分割、ID label と凡例表、表からの生成、分類と Phase の 2 列まで試した。幅の問題は解決したが、どの形でも「表の担当 Phase 列を矢印にしたもの」から先へ進まなかった。幅が足りるかどうかと、図に目的があるかどうかは別の問題だった。

## 表の形

Purpose ごとに節を分ける。

```
### 目的A: 運営が選択の記録を後から確認できる

運営が発送依頼をキャンセルすると、選択されていたサイズを後から確認できない。

| 分類 | 条件 | 担当 Phase |
|---|---|---|
| 記録が保持される | `キャンセルされても行が削除されない`<br>`選んだサイズを DB から取得できる` | Phase 3 |
| 有効な行だけが表示される | `参照する経路が有効な行だけを返す`<br>`管理画面の表示が無効な行で変わらない` | Phase 2, Phase 4 |
```

- Purpose は見出しに、誰が何をできるようになるかを主語と述語のある文で記載する。体言止めの名詞連結 (「サイズ表示」「一覧維持」) にしない
- Context は表の前に 1 文で記載する。誰が、どの状況で困るか。入力に無ければ推測せず `文脈: 未記載` とする
- 1 つのセルに条件を 2 つ以上並べるときは、条件の文の頭に `No.1` `No.2` と上流の順番を付け、`<br>` で改行する。` / ` でつながない。分類は backtick で囲まない
- 条件は Design Doc の条件と同じ番号と語にする。長さを理由に言い換えない。backtick で装飾しない。NG 語を含む原文の扱いは `guidelines/writing/NG-DICTIONARY.md` の「上流 doc からの引用」に従う

## 記載する内容

- **Phase が 3 つ以上のときに作る**。2 つ以下なら本文を読めば対応をたどれるので作らない (依存の向きを記載する閾値と同じにする)
- **条件が 10 件を超えたら分類の行にまとめる** (Design Doc の受け入れ条件の表に分類の列があれば、その分類を使う)。条件の全文は本文の完了条件が示す。分類名は Design Doc の語にし、表のために作った短縮語 (「一覧維持」等) にしない
- **担当条件がなく、他の Phase の後始末だけを担う Phase (使われなくなった実装の削除 等) は表に記載しない**。追跡関係が無いため。この種の Phase の位置は「マージ順序と依存関係」が示す
- 表にだけ存在する要件や Phase を作らない。本文と語を一致させる
- file path、SQL、詳細な signature は記載しない (`spec-gate.sh` の `impl-form` と同じ線引き)
- 表が表すのは追跡関係であって処理順序ではない。実行の順序は「処理フロー」の節、merge の順序は「マージ順序と依存関係」の図が担当する

## 図を置く節との違い

作業計画書の中で図が有効なのは、枝分かれと再結合のある関係に限る。「マージ順序と依存関係」の DAG がその例で、PR #1 から #1b と #2 へ枝が分かれ、#4 で 1 本に戻る。この順序を表で表すと、読み手が自分で辺を改めてたどることになる。

図を置くときは幅を確かめる。`node ~/.claude/scripts/mermaid-width.js --estimate <file> --width 800` が描画せずに見積もり、`spec-gate.sh` の `diagram-width` が同じ式で WARN を表示する。幅を超えた図は切断されず縮小表示されるので、文字が小さくなって読めなくなる。式の根拠は `tests/fixtures/mermaid-width/measured-2026-09-17.md` の実測 30 点にある。
