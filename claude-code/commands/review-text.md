# /review-text — 第三者レビュー視点の問題箇所抽出 (read-only)

内容を知らない読み手が文章を読んで理解できない箇所を、6 観点で列挙する。書き直しはしない (修正は `/jp-fix` へ手渡す)。既存の `/jp-lint` (NG 辞書の機械検査) と `/jp-fix` (書き直し) の中間で、「意味の粗さを人的視点で列挙するだけ」を担う。

## 実行 mode

inline 固定 (read-only、反復しない)。file を Read するか user が paste した text を受け取り、指摘の list を chat に返して終了する。

例外として、`/sdd-design` Step 7.6 は書き手と別の context で読ませるため、この手順を reviewer-agent へ委譲して実行する。

## 引数

| 入力 | 解決 |
|---|---|
| file path | 対象 file を Read する (glob 可)。省略時は直前の会話で扱った text か user が paste した text を対象にする |
| `--stdin` | 直前の user 発言を対象にする (paste した文章のレビュー用) |

## 6 観点

各指摘は「観点 / 該当箇所 (行番号 or 引用 1 句) / 問題の 1 行」の形で返す。書き直し案は書かない。

| 観点 | 確認するもの |
|---|---|
| **主語・目的語の曖昧さ** | 誰が / 何を、が省略されて 2 通り以上に読める箇所。「対応した」「反映した」の主語が誰か / 何を対応したかが特定できない |
| **前提知識への依存** | 説明されていない固有名詞・略語・社内用語・過去 issue 番号・ある 1 PR を読んでいないと成立しない前提 |
| **因果関係の不成立** | 「A なので B」の A から B が導けない / A と B が並列事実で因果でない / 途中の step が省かれている |
| **曖昧な動詞** | 「対応する」「担保する」「合わせる」等、動作の具体を示さない動詞。何をどう変更したかが読めない |
| **具体を含まない印象語** | 「適切に」「必要に応じて」「整理する」「`見直す`」等、聞こえは良いが操作対象と判断基準が無い表現 |
| **元実装から読み取れない断定** | 対象 file / diff / log に書かれていない主張、確認していない挙動を断定している箇所 (対象が code に無い「〜される」「〜になる」「〜されている」) |

## Flow

1. **対象確定**: 引数の file を Read するか、`--stdin` なら直前の user text を対象にする。file が複数なら 1 件ずつ扱う
2. **長文分割**: 対象が 150 行 (or 3000 字) を超える場合、見出し境界 or 段落境界で chunk に分割する。1 chunk あたり 150 行を目安にする。長さに応じて検出密度が下がるのを避けるため、chunk ごとに手順 3-4 を独立して行う (複数 chunk をまとめた要約や間引きをしない)
3. **通読 1 回目 (chunk ごと)**: 内容を知らない読み手を演じて chunk を頭から読み、理解できなかった位置を全部書き留める。この段階で 6 観点への振り分けはしない
4. **6 観点で分類 (chunk ごと)**: 書き留めた箇所を上の表に当てる。1 箇所が 2 観点に該当するときは重い方 1 つを選び、重複計上しない
5. **元実装との照合**: 「元実装から読み取れない断定」の候補は、参照可能なら対象 code / diff を Read して事実か確認する。code を Read できない環境なら「未確認」と明示する
6. **統合**: 全 chunk の指摘を観点ごとに集約する (chunk 番号 or 該当行番号を保持する)
7. **指摘 list 出力**: 観点ごとに 5 件までを上限として列挙する (それ以上あるときは「他 N 件」と件数で示す)。書き直し案は付けない
8. **次手案内**: 1 行で「修正は `/jp-fix <path>` へ」と添えて閉じる。`/jp-fix` 側も含め、この command が出した指摘に基づく修正は diff を提示して user の確認を得てから適用する (無断で書き換えない)

## 出力 format

```
## /review-text 結果

対象: <file path or paste>

### 主語・目的語の曖昧さ
- L<n> 「<引用>」: <問題 1 行>

### 前提知識への依存
- ...

### 因果関係の不成立
- ...

### 曖昧な動詞
- ...

### 具体を含まない印象語
- ...

### 元実装から読み取れない断定
- ...

次手: 修正は `/jp-fix <path>` へ
```

各観点が 0 件なら「なし」と 1 行だけ書く。全 0 件なら「指摘なし」で閉じる。

## Forbidden

- 書き直し案を返す (この command の役割ではない。修正は `/jp-fix` の担当)
- 指摘に基づく修正を diff 提示 + user 確認なしに適用する (`/jp-fix` 側でも同様)
- NG 辞書 (`guidelines/writing/NG-DICTIONARY.md`) の機械検査を代替する (機械検査は `/jp-lint`)
- 指摘の根拠に「AI 臭い」「読みにくい」等の主観だけを記載する (6 観点のどれに該当するかを 1 行で示す)
- 元実装を Read できないのに「code に書かれていない」と断定する (`未確認` と明示する)

## 関連

- `/jp-fix` — 推敲・書き直し (この command で列挙した指摘の修正先)
- `/jp-lint` — NG 辞書の機械検査 (擬人化 / 難読漢語 / 弱い表現の literal 一致)
- `guidelines/writing/PRINCIPLES.md` — 曖昧動詞と圧縮動詞の canonical
- `guidelines/writing/NG-DICTIONARY.md` — 語彙レベルの block list (この command は語彙でなく意味の粗さを扱う)
