# Claude Code Practical Tips

> **Purpose**: Context management / compaction tips for Claude Code operation. Reference when session length or token consumption is a concern.

## Context Management

| Item | Detail |
|------|--------|
| Monitor | Brain mark in statusLine = context size |
| Compaction threshold | Auto compact triggers above 80% → quality degrades |
| **Rule** | **Restart after task completion** (Ctrl-C ×2 or `/exit`) |
| Check | `/context` to view usage |

### Handling Compaction

| Avoid | Recommended |
|-------|-------------|
| Ignore frequent compaction | Turn off auto-compact → use manual `/compact` |
| Do nothing after compact | Run `/reload` after compact to re-read CLAUDE.md |
| Leave session open after task | Restart after completing a task set |

## `.claude/rules/*.md` `paths` glob

- `*.go` matches only files directly under the project root. To make it apply to subdirectories, write `**/*.go` (per the official docs memory 「Path-specific rules table」: `*.md` = "Markdown files in the project root")
- Brace expansion works (`src/**/*.{ts,tsx}`, `{response,view,handler}.go`). The whole `paths` of a single rule has a 1,000-pattern / 4 MiB post-expansion limit; patterns beyond it stay unexpanded and are treated as literals
- A rule is loaded "when Claude reads a file matching the pattern," not on every tool use
- Whether a dotless `*ts` matches `foo.ts` is not documented. Stick to `*.ts`
- Which rules were actually loaded can be checked via the `InstructionsLoaded` hook
- To measure "which CLAUDE.md / rule got loaded" in a fresh session on another repo, run `claude -p --max-turns 3 --allowedTools=Read '<prompt that Reads the target file and then lists the paths under the "Contents of <path>" headings>' < /dev/null` inside that repo (used on 2026-08-28 to verify the effect of removing `claudeMdExcludes`)

## Pattern where a repo treats `.claude/` as a generated artifact (canonical dir + sync script)

In repos that use both Cursor and Claude Code, a common setup is to git-manage a tool-agnostic canonical dir like `shared-rules/{rules,commands,agents,skills}` and have a sync script convert its frontmatter (`description` / `globs` / `alwaysApply`, etc.) into each tool's format, writing out to `.claude/rules` `.claude/commands` `.claude/agents` `.claude/skills` and `.cursor/**`. The generated side is `.gitignore`d and regenerated by `npm install` or husky post-checkout / post-merge.

- **Fix the norms by sending a PR against the canonical dir.** Editing `.claude/` directly gets wiped on the next sync
- **Right after `git worktree add`, the generated artifacts do not exist**, so the repo's slash commands / skills do not appear in the listing and no rules get loaded. Run the sync script once at the worktree root before starting work
- On older branches predating the canonical dir, `.claude/` is tracked and loads as-is, so no sync is needed. Which generation the branch belongs to can be told from "whether `.gitignore` has `.claude/rules/`"
- Rules whose canonical `globs` lack `**/` (`*.go`, etc.) only match files directly under the project root and are not auto-loaded (see the paths glob section above). Explicitly Read them from the canonical dir when touching that area
- Per-repo specifics (canonical dir name / script name / list of unloaded rules) belong in the digest side of org memory, not in this file

## `claude -p` option pitfalls

- Writing `--allowedTools Read '<prompt>'` with whitespace separation makes the variadic option swallow the following prompt as an argument, yielding `Error: Input must be provided either through stdin or as a prompt argument`. Use the `--allowedTools=Read` `=` form, or place the prompt before the option
- When invoking from the Bash tool, append `< /dev/null`. Otherwise the 3-second stdin-wait warning fires every time and pollutes the head of the output
